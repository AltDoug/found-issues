# found-issues 3.3.0: live Codex token measurement (2026-10-06)

Spec §6 ("Task 0") as amended (Decision 5): measure what a Codex auto-fix
run spends per role, so the docs can suggest a token cap. The caps stay
opt-in; nothing in code uses these numbers.

## Streaming usage

`jq -c 'select(.usage) | .type' <id>.fix1.out | sort | uniq -c` gave only
`1 "turn.completed"` for every fixer and verifier output. Codex reports
usage once, at the end of a turn, so a mid-child stop is not possible from
the stream; 3.3.0 keeps "check before each child" (operator decision 3).

## Suggested caps (docs only)

- `RUN_CAP` = 3 × the median pinned spot run (236,626) = 709,878, rounded
  up to the next 100,000: **800000**.
- `SWEEP_CAP` = 3 × the pinned sweep (779,824 for 3 entries) = 2,339,472,
  rounded up: **2400000**.
- The plan's keep-the-old-numbers check: the median spot run is 18% over
  600000/3 but the sweep is 56% over 1500000/3, so the measured values are
  used for both.
- A 3.3.0 sweep has no entry limit, so the sweep number is per sweep of the
  measured size (3 entries, about 260k tokens per entry). A full 8-fix batch
  at that rate is about 2.1M tokens.

## Finding

A launcher-A drain of three spot fixes branched all three from the same
base. Each added a line to `test.sh` and annotated an adjacent ledger line,
so once PRs #1 and #2 merged, PR #3 conflicted and `merge-when-green` gave
up (`GraphQL: Pull Request has merge conflicts (mergePullRequest)`,
`autofix: merging PR #3 failed` in `spawn.log`). The conflict was resolved
by hand for this measurement (merge main into the PR branch, keep both test
lines, re-annotate the ledger). Logged as a decide entry at
`lib/autofix-ship.sh:231`. The inherit spot fixes ran one at a time, each
after the previous PR merged, and all merged themselves.
